# 야구 ABS 존 오버레이

오퍼레이터가 브라우저에서 클릭한 지점을 스트라이크 존 좌표로 변환해 OBS 송출 화면에 오버레이한다.

설계 문서: `../docs/superpowers/specs/2026-09-02-abs-zone-overlay-design.md`

## 실행

```bash
npm install
npm start
```

- 오퍼레이터 콘솔: http://127.0.0.1:3001/console.html
- 송출 오버레이: http://127.0.0.1:3001/overlay.html

포트를 바꾸려면 `PORT=4000 npm start`.

⚠️ **`localhost` 대신 `127.0.0.1`을 쓸 것.** 서버는 `127.0.0.1`(IPv4)에만 바인딩되는데
Windows에서 `localhost`는 `::1`(IPv6)로 먼저 해석된다. 브라우저는 대개 IPv4로 폴백하지만
OBS 브라우저 소스를 포함해 클라이언트마다 동작이 다를 수 있다.

요청한 포트가 이미 쓰이고 있으면(예: 이전 세션이 아직 떠 있음) 죽지 않고 하나씩 올려가며
빈 포트를 찾는다(최대 20회). 실제로 뜬 포트는 콘솔 로그의 URL로 확인한다 — OBS 브라우저
소스 URL도 그 포트로 맞춰야 한다.

서버는 기본적으로 `127.0.0.1`에만 바인딩된다. 인증이 없으므로 다른 기기에서 콘솔을 열려면 `HOST=0.0.0.0 npm start`로 명시적으로 열어야 하고, 그때는 같은 네트워크의 누구나 송출 그래픽을 조작할 수 있음을 알고 있어야 한다.

## OBS 설정

| 항목 | 값 |
|---|---|
| 소스 종류 | 브라우저 |
| URL | `http://127.0.0.1:3001/overlay.html` |
| 폭 × 높이 | 1920 × 1080 |
| 보이지 않을 때 소스 종료 | **끄기** |
| 사용자 지정 CSS | 비움 |

첫 실행 시 콘솔에서 `보정 모드`를 켜고 송출 X/Y/크기 슬라이더로 존을 포수 뒤 카메라 앵글의 홈플레이트에 맞춘다. 이 값은 `config.json`에 저장되어 다음 실행에 복원된다.

## 조작

| 동작 | 방법 |
|---|---|
| 투구 기록 | 존 뷰의 빈 곳 클릭 |
| 공 선택 | 공 클릭 또는 `1`~`9` (해당 순번) |
| 선택 해제 | `Esc` |
| 공 이동 | 공을 잡고 드래그 (놓는 순간 송출 반영) |
| 미세 조정 | 선택 후 방향키 (`Shift` 동시: 5px) |
| 공 삭제 | 선택 후 `Delete` 또는 `Backspace` |
| 되돌리기 | `Ctrl+Z` (macOS는 `Cmd+Z`) |
| 보정 모드 | `C` |

`이닝 종료`·`이전 이닝`·`다음 이닝`·`이닝 초기화`·`모두 지우기`에는 단축키가 없다. 오타 한 번에 이닝이 넘어가는 사고를 막기 위한 것이다.

### 이닝 이동

| 버튼 | 동작 |
|---|---|
| `이닝 시작` | idle/ended → live. ended에서 누르면 같은 이닝을 이어간다(화면을 지우지 않는다) |
| `이닝 종료` | live → ended. 이때 `data/<날짜>.json`에 그 이닝이 저장된다 |
| `이전 이닝` | 이닝을 하나 내리고 **그 이닝의 저장된 기록을 되살려 편집 가능한 상태(live)로** 만든다 |
| `다음 이닝` | ended에서만. 이닝을 하나 올리고 빈 화면으로 live 시작 |
| `이닝 초기화` | 1회 idle 빈 화면으로 되돌린다 |

- `이전 이닝`은 잘못 기록한 이닝을 고치러 돌아가는 용도라 **live 중에도 쓸 수 있다**(1회에서만 비활성). 고친 뒤 `이닝 종료`를 누르면 그 이닝 저장분이 갱신된다.
- 저장된 기록에는 id가 없으므로(`store.saveInning`이 seq·x·z·verdict만 남긴다) 되살릴 때 id를 새로 부여한다. 이게 없으면 되살린 공을 선택·이동·삭제할 수 없다.
- `이닝 초기화`는 **저장된 기록 파일을 지우지 않는다.** 화면과 이닝 번호만 되돌리므로 `다시보기`로 이전 기록을 계속 꺼내 볼 수 있다. 되돌릴 수 없는 삭제를 버튼 하나에 묶지 않기 위한 것이다.
- 이닝을 넘나들면 **되돌리기 스택이 비워진다.** 되돌리기는 한 이닝 안의 편집에만 의미가 있고, 스택을 넘겨주면 새 이닝에서 `Ctrl+Z` 한 번에 직전 이닝의 공이 되살아난다.

## 저장되는 파일

- `data/<YYYY-MM-DD>.json` — 이닝별 투구 기록. `다시보기`로 다시 송출할 수 있다
- `config.json` — 존 종횡비와 송출 배치 보정값

둘 다 git에 올리지 않는다.

## 테스트

```bash
npm test
```

렌더링과 OBS 합성은 자동 테스트 대상이 아니다. 아래 체크리스트로 수동 확인한다.

## 수동 검증 체크리스트

- [ ] OBS 브라우저 소스에서 배경이 투명하다 (아래 영상이 보인다)
- [ ] 존 테두리·공·라벨이 흰 배경과 밝은 하늘 위에서 모두 읽힌다
- [ ] 공을 드래그하는 동안 OBS 화면의 공이 움직이지 않는다
- [ ] 마우스를 놓는 순간 OBS 화면의 공이 새 위치로 한 번에 이동한다
- [ ] OBS 씬을 전환해 소스를 리로드해도 현재 상태가 그대로 복원된다
- [ ] 서버를 껐다 켜면 양쪽이 자동 재연결되고 보정값이 복원된다
- [ ] 서버가 꺼진 동안 OBS 화면이 지워지지 않는다
- [ ] OBS 화면에 존 사각형과 공만 보이고 글자가 하나도 나오지 않는다 (이닝·볼카운트 라벨 없음)
- [ ] 다시보기 중에도 OBS 화면에 아무 라벨이 뜨지 않는다 — ⚠️ **오버레이만 보고는 라이브인지 다시보기인지 구분할 수 없다.** 콘솔의 차단막과 `라이브 복귀` 버튼으로만 확인된다
- [ ] `이전 이닝`으로 돌아가면 그 이닝의 공이 되살아나고, 되살아난 공을 클릭·드래그·삭제할 수 있다
- [ ] `이닝 초기화` 후에도 `다시보기` 드롭다운에 이전 이닝 목록이 그대로 남아 있다
- [ ] OBS 브라우저 소스를 1920×1080이 아닌 크기(예: 1600×1000)로 두었을 때 존이 비대칭으로 늘어나지 않는지 — 늘어나면 소스 크기를 16:9로 맞추거나 `overlay.js`의 CSS 크기 지정을 고쳐야 한다
