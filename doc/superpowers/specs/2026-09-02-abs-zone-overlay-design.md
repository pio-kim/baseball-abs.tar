# 야구 ABS 존 오버레이 — 설계 지시서

- **작성일**: 2026-09-02
- **대상**: OBS Studio 브라우저 소스 + 로컬 웹 서버 (Node.js 20)
- **개발 환경 제약**: 이 문서를 작성한 세션은 Linux ARM 환경이다. OBS Studio가 없으므로 **브라우저 소스 합성의 최종 검증은 OBS가 설치된 머신에서 수행한다.** 로직·상태 전이·판정은 작성 환경에서 자동 테스트로 검증 가능하다.

---

## 1. 목적

야구 중계 화면에 ABS(Automatic Ball-Strike) 스트라이크 존을 오버레이하고, 오퍼레이터가 브라우저에서 마우스로 클릭한 지점을 "공이 지나간 위치"로 송출 화면에 표시한다.

이닝 단위로 세션을 관리하며, 이닝 동안 찍힌 공은 누적 표시되고 이닝 종료 시 파일로 저장된다. 저장된 이닝은 다시 불러 송출할 수 있다.

**범위 내**: 오퍼레이터 콘솔, 송출 오버레이, 스트라이크/볼 자동 판정, 이닝 세션 관리, 공 위치 수정, 이닝별 기록 저장 및 다시보기.

**범위 외**: 실제 투구 추적 하드웨어 연동, 토구유형·구속 라벨, 타자별 신장 보정, 로스터 관리, 인증, 자동 페이드아웃.

## 2. 확정된 설계 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 송출 방식 | OBS Studio **브라우저 소스** | 투명 배경 HTML 한 장으로 끝난다. 별도 송출 장비·NDI 불필요 |
| 스택 | Node.js + `ws` + 바닐라 JS/Canvas | 빌드 단계가 없어 OBS가 URL을 바로 읽는다. 의존성 1개 |
| 투구 좌표 | **정규화 존 좌표** (`x`, `z` ∈ 실수, ±1이 존 경계) | 판정 기준이 상수가 되어 렌더링과 판정이 어긋날 여지가 없다. 해상도 독립 |
| 판정 주체 | **서버 단독** | 콘솔과 오버레이가 각자 계산하면 두 화면이 다른 결론을 낼 수 있다 |
| 전송 방식 | 매 변경마다 **전체 상태 브로드캐스트** (WebSocket) | 패킷 유실이 화면을 영구히 틀어놓지 않는다. OBS는 씬 전환 시 리로드되므로 늦게 붙은 클라이언트도 자동으로 올바른 화면을 갖는다 |
| 존 정의 | **고정 존 1개**, 종횡비를 마우스로 조절 | 타자별 신장 보정은 범위 외. 오퍼레이터 부담 최소 |
| 조절 대상 분리 | `zone.aspect`(판정용)와 `placement`(송출 배치용)를 **별도 값**으로 | 합치면 "카메라 앵글 맞추려 존을 늘렸는데 판정이 바뀌는" 버그가 구조적으로 생긴다 |
| 공 누적 | 이닝 동안 누적 표시, 이닝 전환 시 초기화 | 중계 그래픽의 통상 형태 |
| 볼카운트 | **표시하지 않음** | 타석 경계를 프로그램이 알 수 없어 정확히 셀 수 없다. 방송사 스코어뱅크가 이미 표시한다 |
| 수정 중 송출 | 드래그 중에는 미반영, **`mouseup`에 1회 반영** | 시청자가 흔들리는 공을 보지 않는다 |
| 되돌리기 | `pitches` **상태 스냅샷 스택** (최근 20개) | 각 동작의 역연산을 구현하는 것보다 단순하고 버그가 없다. 데이터가 작아 메모리 부담이 없다 |
| 파괴적 동작 확인 | 모달 없이 **버튼 2단 확인** (3초 내 재클릭) | 방송 중 모달은 포커스를 훔치고 단축키를 먹는다 |

### 의도적으로 포기한 것

- **타자별 존 높이 보정** — KBO ABS는 타자 신장 대비 상단 56.35% / 하단 27.64%로 존을 산출한다. 정확하지만 투구 전에 타자 키를 알아야 하고 로스터 관리 화면이 필요하다. 필요해지면 `zone`에 `heightCm` 필드를 추가하고 `aspect`를 계산값으로 대체하는 형태로 국소 확장한다.
- **여러 이닝 동시 표시** — 오버레이는 항상 한 이닝(또는 다시보기 중인 한 이닝)만 그린다.
- **되돌리기의 이닝 전이 포함** — 이닝 전이는 2단 확인과 `ended → 이닝 시작` 복구 경로로 이미 보호된다.
- **다중 오퍼레이터 / 권한 분리** — 로컬 단일 오퍼레이터 전제. 콘솔 URL을 아는 누구나 조작할 수 있다.

## 3. 파일 구조

```
abs-overlay/
  server.js              HTTP 정적 서버 + WebSocket 허브. 상태의 단일 소스
  state.js               상태 기계 + 전이 함수 + 되돌리기 스택 (순수)
  store.js               이닝 기록 ↔ JSON 파일
  public/
    zone.js              좌표 변환 + 스트라이크 판정 (순수, 서버·양쪽 화면 공유)
    console.html/.js/.css  오퍼레이터 콘솔
    overlay.html/.js       OBS 브라우저 소스용 렌더러
  data/
    2026-09-02.json      (실행 시 생성) 경기별 이닝 기록
  config.json            (실행 시 생성) zone / placement 보정값
  tests/
    zone.test.js
    state.test.js
    store.test.js
    server.test.js
  package.json
```

### 모듈 계약

각 모듈은 다른 모듈의 내부를 알지 못한다. `server.js`만 넷을 조립한다.

| 모듈 | 공개 함수 | 의존 |
|---|---|---|
| `zone.js` | `toNormalized(px, py, rect) → {x, z}` <br> `toPixels(x, z, rect) → {px, py}` <br> `judge(x, z) → 'strike' \| 'ball'` | 없음 (순수) |
| `state.js` | `createState() → state` <br> `transition(state, action) → {state, effects}` <br> `undo(state) → state` | `zone.js` |
| `store.js` | `saveInning(date, inning, pitches)` <br> `loadInning(date, inning) → pitches` <br> `listInnings(date) → number[]` <br> `loadConfig() / saveConfig(cfg)` | 없음 (파일 I/O만) |
| `server.js` | (진입점) | 셋 전부 + `ws` |

`transition`이 순수 함수이고 부수효과를 `effects`로 반환하는 것이 핵심이다. 파일 저장·브로드캐스트를 `server.js`가 수행하므로 상태 기계 전체를 파일 시스템 없이 테스트할 수 있다.

## 4. 좌표계

투구 위치는 픽셀이 아니라 **정규화 존 좌표**로 저장한다.

```
x: 좌우.  0 = 존 중앙,  ±1 = 존 좌우 경계
z: 상하.  0 = 존 중앙,  +1 = 존 상단,  -1 = 존 하단

판정:  |x| ≤ 1 && |z| ≤ 1  →  strike,  그 외 ball
```

이 설계가 보장하는 것:

1. **판정 기준이 상수** — 존 사각형을 어떻게 리사이즈해도 경계는 항상 ±1. 렌더링과 판정이 어긋날 구조적 여지가 없다.
2. **송출 배치는 판정에 무영향** — 배치 보정은 정규화 좌표를 화면 픽셀로 되돌리는 마지막 단계만 건드린다.
3. **해상도 독립** — 1080p, 4K, 세로형 클립에 같은 데이터를 쓴다.

`z`의 부호가 화면 좌표(아래로 증가)와 반대인 점에 주의한다. `toPixels`가 부호를 뒤집는 유일한 지점이며, 이 변환은 `zone.js` 안에만 존재해야 한다.

## 5. 상태 모델

```js
// 서버가 보유하는 단일 진실
{
  zone:      { aspect: 1.0 },                    // 판정 존 종횡비 (폭/높이)
  placement: { x: 0.5, y: 0.45, scale: 0.22 },   // 송출 화면 내 중심 위치와 크기 (뷰포트 비율)
  game: {
    inning:  3,
    status:  'idle' | 'live' | 'ended',
    pitches: [ { id: 'p1', seq: 1, x: 0.31, z: -0.82, verdict: 'strike' }, … ]
  },
  review: null | { inning: 1, pitches: [ … ] }   // 다시보기 중이면 채워짐
}
```

`zone`과 `placement`는 `config.json`에 영속화되어 재시작 시 복원된다. `game`과 `review`는 휘발성이다.

### 콘솔 로컬 상태 (서버로 올리지 않는다)

| 값 | 이유 |
|---|---|
| `mode` (보정/입력) | 오퍼레이터가 보정 모드에 있는 사실을 오버레이가 알 필요가 없다 |
| `selectedId` | 선택 표시는 콘솔에만 필요하다 |
| 드래그 중 좌표 | **이것이 서버로 가면 곧 송출 반영이다.** 올리지 않음으로써 드래그가 송출에 새는 일을 물리적으로 불가능하게 만든다 |

### `id`와 `seq`

- `id`는 삭제·이동 대상을 지목하기 위한 내부 식별자다. 화면에 표시하지 않는다.
- `seq`는 화면에 표시되는 순번이며, **삭제 시 재부여한다** (1, 2, 3). 잘못 찍은 공은 애초에 없던 투구이므로 송출 화면에 `1, 3, 4` 같은 구멍을 남길 이유가 없다.

## 6. 상태 기계

```
        ┌──── 이닝 시작 ────┐
        ▼                   │
     [live] ─ 이닝 종료 ─► [ended]
        │                   │
   클릭=기록            ┌───┴─── 다음 이닝 ──► [live] (inning+1, 화면 초기화)
                        └─── 이닝 시작 ──► [live] (같은 이닝 재개, 화면 유지)

  프로그램 시작 → [idle] ─ 이닝 시작 ─► [live]
```

### 전이 표

| 현재 | 액션 | 결과 | 부수효과 |
|---|---|---|---|
| `idle` | `INNING_START` | → `live`, `pitches = []` | — |
| `live` | `PITCH_ADD {x, z}` | `pitches`에 판정된 공 추가, `seq` 부여 | 스냅샷 push |
| `live` | `PITCH_MOVE {id, x, z}` | 해당 공의 좌표 갱신, **판정 재계산** | 스냅샷 push |
| `live` | `PITCH_DELETE {id}` | 해당 공 제거, `seq` 재부여 | 스냅샷 push |
| `live` | `PITCH_CLEAR_ALL` | `pitches = []` | 스냅샷 push |
| `live` | `UNDO` | 스냅샷 스택에서 pop | — |
| `live` | `INNING_END` | → `ended` | **기록 저장** |
| `ended` | `INNING_START` | → `live` (`pitches` 유지) | — |
| `ended` | `INNING_NEXT` | → `inning + 1`, `live`, `pitches = []` | — |
| 모든 상태 | `REVIEW_ENTER {inning}` | `review` 채움 | 기록 로드 |
| 모든 상태 | `REVIEW_EXIT` | `review = null` | — |
| 모든 상태 | `ZONE_SET` / `PLACEMENT_SET` | 해당 값 갱신 | `config.json` 저장 |

**표에 없는 (상태, 액션) 조합은 모두 무시하고 경고 로그를 남긴다.** 특히 `idle`/`ended`/`review` 상태의 `PITCH_*`는 무시된다.

### 입력 가능 조건

```js
canInput = state.game.status === 'live' && state.review === null
```

**이 조건은 `state.js` 안에 단 한 번만 등장한다.** 콘솔은 이 값을 서버로부터 받아 쓰고, 스스로 판단하지 않는다. 조건이 흩어지면 반드시 어긋난다.

### `ended → INNING_START`를 허용한 이유

실수로 `이닝 종료`를 눌렀을 때 되돌릴 경로가 된다. 같은 이닝을 재개해 공을 더 찍고 다시 종료하면, `store.js`가 해당 이닝 항목을 **교체**하므로 중복 기록이 생기지 않는다.

## 7. 저장 형식

### `data/<YYYY-MM-DD>.json` — 하루(경기) 한 파일

```json
{
  "date": "2026-09-02",
  "innings": [
    {
      "inning": 1,
      "endedAt": "2026-09-02T06:12:44.000Z",
      "pitches": [
        { "seq": 1, "x": 0.31, "z": -0.82, "verdict": "strike" },
        { "seq": 2, "x": 1.24, "z": 0.10, "verdict": "ball" }
      ]
    }
  ]
}
```

- 같은 `inning`을 다시 종료하면 해당 항목을 **교체**한다 (배열에 추가하지 않는다).
- `id`는 저장하지 않는다. 내부 식별자일 뿐이다.
- 파일 쓰기는 임시 파일에 쓴 뒤 `rename`한다. 저장 도중 프로세스가 죽어도 기존 기록이 깨지지 않는다.

### `config.json`

```json
{ "zone": { "aspect": 1.0 }, "placement": { "x": 0.5, "y": 0.45, "scale": 0.22 } }
```

없으면 기본값으로 생성한다.

## 8. 오퍼레이터 콘솔

### 레이아웃

```
┌────────────────────────────────────────┬──────────────────────────┐
│                                        │  3회         ● LIVE      │
│          ┌───────────────┐             │                          │
│          │   ②       ①   │             │  [    이닝 종료    ]     │
│          │       ③       │  ③ = 선택   │  [    다음 이닝    ]     │
│          │       ⌾       │  ⌾ = 고스트 │                          │
│          └───────────────┘             │  ──── 다시보기 ────      │
│              x +0.31 / z −0.82         │  [ 1회 ▾ ]   [ 보기 ]    │
│                                        │  [   라이브 복귀   ]     │
│         투구 3    S 2 · B 1            │                          │
│                                        │  ──── 편집 ────          │
│      ← 클릭 영역: 존의 2.5배 →         │  [  되돌리기  ⌃Z  ]      │
│                                        │  [   선택 삭제    ]      │
│                                        │  [  모두 지우기   ]      │
│                                        │                          │
│                                        │  □ 보정 모드 (C)         │
│                                        │  ● 연결됨                │
└────────────────────────────────────────┴──────────────────────────┘
```

클릭 영역은 존의 **2.5배**다. 볼을 찍으려면 존 밖을 클릭해야 하기 때문이다. 존 경계는 실선, 그 밖은 흐린 격자 배경으로 구분한다.

### 두 개의 모드

| 모드 | 클릭 | 드래그 |
|---|---|---|
| 입력 모드 (기본) | 투구 추가 / 공 선택 | 선택된 공 이동 |
| 보정 모드 (`C`) | **무시** | 존 리사이즈 / 배치 조정 |

라이브 중에 실수로 존을 끌어버리는 사고를 구조적으로 막는다.

### 상호작용 규칙

```
mousedown
 ├─ 보정 모드           → 존 리사이즈 / 배치 조정
 └─ 입력 모드
     ├─ 기존 공 반경 14px 안?  → 그 공을 선택 (드래그 후보)
     └─ 빈 곳?                 → 새 공 추가 후보

mousemove (버튼 누른 채)
 ├─ 이동 < 3px            → 아무 일 없음
 └─ 이동 ≥ 3px
     ├─ 선택된 공 있음     → 고스트 미리보기로 따라 이동 (송출 미반영)
     └─ 없음               → 아무 일 없음

mouseup
 ├─ 드래그였다      → PITCH_MOVE 전송
 ├─ 클릭 + 기존 공  → 선택만 (서버 통신 없음)
 └─ 클릭 + 빈 곳    → PITCH_ADD 전송
```

**드래그로는 새 공이 만들어지지 않는다.** 손이 미끄러져도 의도하지 않은 공이 송출로 나가지 않는다.

### 드래그 중 시각 피드백

- 원래 위치에 반투명 **고스트**, 새 위치에 실선 마커 → 이동량이 보인다.
- **판정이 바뀌는 순간 색이 즉시 변한다** (스트라이크 빨강 ↔ 볼 파랑). 존 경계를 넘겼는지 놓기 전에 알 수 있다.
- 커서: 공 위 `grab` / 드래그 중 `grabbing` / 빈 곳 `crosshair`.

경계에 걸친 공이야말로 수정이 필요한 상황인데, 놓아본 뒤에야 판정을 알게 되면 고치고 또 고치게 된다.

### 단축키

| 키 | 동작 |
|---|---|
| `1`~`9` | 해당 순번 공 선택 |
| `← ↑ ↓ →` | 선택된 공 1px 이동 (`Shift` 동시: 5px) |
| `Delete` / `Backspace` | 선택된 공 삭제 |
| `Esc` | 선택 해제 |
| `Ctrl+Z` | 되돌리기 |
| `C` | 보정 모드 토글 |

방향키 이동은 즉시 송출 반영하되(1px이라 시각적 부담이 없다), 연타를 **300ms 디바운스**로 묶어 되돌리기 한 번에 원복되게 한다.

**`이닝 종료` · `다음 이닝` · `모두 지우기`에는 단축키를 주지 않는다.** 오타 한 번에 이닝이 넘어가는 사고를 원천 차단한다.

### 파괴적 동작 확인

`다음 이닝`, `모두 지우기`는 공이 하나라도 있으면 **버튼 자체가 2단으로 동작**한다: 누르면 라벨이 `정말 지울까요?`로 바뀌고, 3초 안에 다시 누르면 실행, 아니면 원복.

### 입력 불가 상태 표시

`canInput`이 거짓이면 **클릭 영역 전체를 어둡게 덮고 중앙에 이유와 해법을 표시**한다.

| 상황 | 문구 |
|---|---|
| `idle` | `이닝 시작을 눌러주세요` |
| `ended` | `3회 종료됨 — 이닝 시작 또는 다음 이닝` |
| `review` | `1회 다시보기 중 — 라이브 복귀` |
| 연결 끊김 | `서버 연결 끊김 — 재연결 중…` |

오퍼레이터가 "찍었는데 안 나갔다"를 모르는 상황을 없앤다.

## 9. 송출 오버레이

### 렌더링

- `body { background: transparent }` — OBS 브라우저 소스가 이를 알파 채널로 인식한다.
- Canvas는 소스 해상도(1920×1080)에 고정, `devicePixelRatio` 보정.
- 그리는 것: 존 테두리 / 공 마커(순번 숫자 + 스트라이크·볼 색 구분) / 이닝 번호 / S·B 개수 요약.
- **가장 최근 공만 더 크고 밝게** 그린다. 방금 찍은 게 어느 것인지 한눈에 보여야 한다.
- **모든 요소에 어두운 외곽선과 그림자를 넣는다.** 중계 영상의 배경은 흰 유니폼일 수도 밝은 하늘일 수도 있어, 외곽선 없는 흰 선은 수시로 사라진다.
- 애니메이션은 공 마커 등장 시 **150ms 스케일-인** 하나만. 그 외에는 정적.
- 다시보기 중이면 좌상단에 **`3회 다시보기`** 라벨을 띄운다. 라이브인 줄 알고 송출하는 사고를 막는다.

오버레이는 입력을 받지 않는다. 상태를 받아 **전체를 다시 그린다.**

### OBS 설정

| 항목 | 값 |
|---|---|
| 소스 종류 | 브라우저 |
| URL | `http://localhost:3000/overlay.html` |
| 폭 × 높이 | 1920 × 1080 |
| 보이지 않을 때 소스 종료 | **끄기** (끊김 방지) |
| 사용자 지정 CSS | 비움 |

콘솔은 별도 브라우저 창에서 `http://localhost:3000/console.html`.

## 10. 오류 처리

방송용의 원칙: **화면이 사라지는 게 최악이다.** 일반 웹앱과 방향이 반대다.

| 상황 | 오버레이 | 콘솔 |
|---|---|---|
| WS 끊김 | **마지막 상태를 그대로 유지**하고 조용히 재연결 (지수 백오프, 최대 5초 간격). 화면을 지우지 않는다 | 연결 배지를 빨강으로, 클릭 영역을 덮고 `재연결 중…` 표시 |
| 서버 재시작 | 재연결 후 새 상태 수신 | 같음 |
| 알 수 없는 메시지 | 무시 | 무시 |

- 서버는 전이 표에 없는 액션을 무시하고 경고 로그만 남긴다. 예외를 던져 프로세스를 죽이지 않는다.
- `config.json` / `data/*.json`이 손상되면 경고 로그와 함께 기본값으로 시작한다. 파일 하나 때문에 방송 중 서버가 못 뜨는 상황을 만들지 않는다.
- 저장 실패 시 콘솔에 오류를 표시하되 상태 전이는 진행한다. 저장 실패가 이닝 진행을 막으면 안 된다.

## 11. 테스트

`node:test` 사용. 렌더링만 수동 확인한다.

### `zone.test.js`
- `toNormalized` / `toPixels` 왕복 변환이 원값을 복원하는지
- `z` 부호 반전이 올바른지 (존 상단이 화면 위쪽인지)
- **경계값 판정**: `|x| == 1`, `|z| == 1`은 `strike`. `1.0001`은 `ball`
- `aspect`가 달라도 판정 경계가 ±1로 불변인지

### `state.test.js`
- **전이 표 전체**를 표 그대로 테스트
- `ended → INNING_START`가 화면을 지우지 **않는지**
- `ended → INNING_NEXT`가 화면을 지우고 이닝을 올리는지
- **입력 게이트**: `idle` / `ended` / `review` 상태의 `PITCH_*`가 무시되는지
- **히트 테스트 경계**: 반경 14px 안/밖
- **드래그 임계값**: 2px 이동은 클릭, 4px는 드래그로 판정되는지
- **이동 후 판정 재계산**: 존 안에서 밖으로 옮기면 `verdict`가 `ball`로 바뀌는지
- **삭제 후 seq 재부여**: 2번을 지우면 3번이 2번이 되는지
- **되돌리기 스택**: 추가·이동·삭제·전체삭제가 각각 원복되는지. 20개 초과 시 오래된 것이 버려지는지
- `PLACEMENT_SET`이 어떤 공의 `verdict`도 바꾸지 않는지 — 판정·배치 분리를 직접 겨냥한다

### `store.test.js`
- 같은 이닝을 두 번 종료해도 `innings` 항목이 하나인지 (교체)
- 손상된 JSON을 만나면 예외 대신 기본값을 반환하는지
- 임시 파일 + `rename` 경로가 기존 파일을 깨지 않는지

### `server.test.js`
- WS 클라이언트 2개를 붙여 한쪽이 투구를 보내면 **양쪽이 동일한 상태**를 받는지 — 판정 일원화가 지켜지는지 보는 테스트
- 늦게 접속한 클라이언트가 즉시 현재 전체 상태를 받는지
- **드래그 중 송출 미반영**: `PITCH_MOVE`가 `mouseup`에서만 1회 전송되는 프로토콜인지 (콘솔이 드래그 중 메시지를 보내지 않음을 검증)
- `REVIEW_ENTER` 중 라이브 상태가 변하지 않고, `REVIEW_EXIT` 후 온전한지

## 12. 설계를 지배하는 원칙

이 문서의 판단들은 대부분 같은 원칙의 반복이다.

1. **섞이면 사고가 나는 것을 구조적으로 분리한다** — 판정 존과 송출 배치, 휘발성 화면 상태와 영구 기록, 라이브와 다시보기, 콘솔 로컬 상태와 서버 상태. 규율로 지키는 것보다 구조로 막는 것이 값싸게 안전하다.
2. **실수의 비용에 비례해 마찰을 준다** — 공 찍기는 클릭 한 번, 공 옮기기는 드래그 임계값 3px, 이닝 넘기기는 2단 확인과 단축키 없음.
3. **결과를 행동 전에 보여준다** — 드래그 중 판정 색 변화. 확정 후 확인하는 UI는 시도-실패-재시도 루프를 만들고, 그 루프가 라이브 방송에서는 시청자에게 노출된다.
4. **현재 상태를 화면이 스스로 말한다** — 입력 불가 오버레이, 다시보기 라벨, 연결 배지.
5. **설계 원칙마다 그것을 깨면 빨개지는 테스트를 붙인다** — 판정 일원화, 판정·배치 분리, 드래그 미반영은 모두 전용 테스트를 갖는다.
